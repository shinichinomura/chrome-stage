# offscreen parking 検証結果

検証日: 2026-07-03
環境: macOS(Darwin 25.5.0)/ ディスプレイ 1710x1107(単一)/ 対象ウィンドウ 1710x1073

## 結論

**offscreen parking は「1px だけ画面内に残す」方式で成立する。** 設計メモの「x: -20000 に飛ばす」案はそのままでは成立しない(macOS が位置を補正する)ため、退避座標の算出方法を変更して Phase 1 を進める。

## 検証結果

| パターン | 要求座標 | 実際 | 判定 |
|---|---|---|---|
| 左に大きく飛ばす(設計メモ案) | (-20000, 100) | (-1670, 100) | クランプ(約 40px が画面内に残る) |
| 右に大きく飛ばす | (+20000, 100) | (1670, 100) | クランプ(同上) |
| 下に大きく飛ばす | (100, +20000) | (100, 1066) | クランプ(上端 41px が画面内に残る) |
| 左にウィンドウ幅+1px | (-1711, 34) | (-1670, 34) | クランプ |
| **1px だけ画面内に残す(左端)** | (-1709, 34) | (-1709, 34) | **要求どおり** |
| 下端ギリギリ | (0, 1106) | (0, 1066) | クランプ |
| **1px だけ画面内に残す(右端)** | (1709, 34) | (1709, 34) | **要求どおり** |
| 右端 1px + 下端 | (1709, 1106) | (1709, 1066) | y のみクランプ |

## わかったこと

- WindowServer は「完全に画面外」を要求されると、**横方向は約 40px、縦方向(下)は約 41px** が画面内に残る位置へ補正する
- ただし **1px でも画面内に残る座標は補正されずそのまま通る**。つまり横方向は `x = -(width - 1)` または `x = screenMaxX - 1` が退避座標として使える
- 縦方向は下端 1px 残しができない(タイトルバー相当が画面内に強制される)ため、**退避は横方向で行う**
- AXError はクランプ時も 0(success)を返すため、**操作後に実座標を読み直して検証する実装が必須**(CLAUDE.md の方針どおり)
- 元の位置への復帰は正確に動作する

## Phase 1 実装への反映

1. **退避座標の算出**: 固定値ではなく、park 実行時にウィンドウ幅と対象ディスプレイの frame から `x = screenMinX - (width - 1)`(左端)or `x = screenMaxX - 1`(右端)を計算する
2. **park 後の検証**: 位置設定後に読み直し、要求とずれていたら再計算してリトライする(クランプ幅 40px は macOS バージョンで変わる可能性があるため、実測ベースで扱う)
3. **1px スリットの視認性**: 画面端に 1px の帯とそのドロップシャドウがわずかに見える可能性がある。Overlay UI や実利用で気になるかは Phase 1 の実機確認項目に含める(気になる場合は退避先を「マウスが届きにくい側の端」に寄せる等で調整)
4. **マルチディスプレイ**: 退避座標は対象ディスプレイの frame 基準で計算する。ディスプレイ構成変更時の再計算は設計どおり必須

## 実行方法

```
cd spikes/offscreen-parking
swift main.swift
```

前提: 実行プロセスに Accessibility 権限があり、Chrome の通常ウィンドウが開いていること。
